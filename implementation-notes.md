# Implementation Notes — Agora Scout

## 2026-05-29 — Public commit-then-act verifier
- **Decisión:** Endpoint read-only `GET /api/verify/{id}` + botón "Verify on-chain" por rebalance. Verificación en 2 niveles: (L1) decision_hash guardado == calldata on-chain; (L2) recompute SHA-256 del payload canónico == decision_hash. Juntos = cadena `payload → hash → on-chain`.
- **Razón:** El pitch reclamaba "tamper-proof, verifiable on Arcscan" sin forma de verificarlo. Esto lo vuelve un feature provable = entrega el "audit layer" prometido en el grant de Circle. EV+ alto para jueces de un primitive de accountability.
- **Tradeoff:** Requirió persistir `decision_payload` canónico nuevo en tabla rebalances (antes solo guardaba el hash → no recomputable). Migración idempotente. Filas legacy (sin payload) verifican solo L1; nuevas obtienen L1+L2.
- **Seguridad:** Endpoint 100% read-only (cero writes/capital). `rebalance_id: int` en path → non-int = 422 (anti-injection). RPC solo lectura (`eth_getTransactionByHash`) vía cliente web3 key-free.
- **Cambios al plan:** VPS config.py y requirements.txt estaban DIVERGENTES del repo local (config sin ARC_PRIVATE_KEY/CHAIN_ID/ARCSCAN_TX_BASE; requirements sin web3==7.6.0). El `--build` reveló la divergencia (web3 faltaba → rompía anchoring+verifier). Fix: append 3 attrs a config.py VPS + scp requirements.txt correcto. VPS git queda divergente (chain.py untracked allí) — deploy por scp directo al working tree, NO git pull.
- **Verificado:** unit tests 4/4 (hash recompute + tamper); /api/verify/113 live → verified=true (L1, calldata==hash); 404 missing / 422 non-int OK; público vía funnel OK; frontend sirve VerifyButton sin errores transform.

## 2026-06-08 — Fix layout dashboard: safe-card colapsada (tira vertical)
- **Síntoma:** En `/dashboard` ancho, el `.safe-card` (veredicto + meter + confianza) colapsaba a una tira fina vertical en el centro; el donut se comía el resto → centro vacío.
- **Causa:** Edits locales sin commitear cambiaron `.status-row` y `.dec-grid` de CSS Grid → flexbox (`flex:1.45 1 0;min-width:0`). En flex, el safe-card se encogió a min-content pese a `min-width:0`; el donut con `flex:1` tomó el espacio. La versión Grid (committeada) funcionaba.
- **Decisión:** Revertir ambos a Grid pero con `grid-template-columns:minmax(0,1.45fr) minmax(0,1fr)` (status-row) y `minmax(0,1.4fr) minmax(0,1fr)` (dec-grid). `minmax(0,…)` llena el track Y evita blowout por texto largo — más robusto que el Grid original sin minmax. Tradeoff: Grid sobre flex porque los tracks de Grid siempre honran el sizing; flex colapsa a min-content en este árbol.
- **Conservado:** spans nowrap en App.jsx (arc-pill, market-flag) y bloque guard `flex-direction:row !important` — inofensivos, atacan el bug previo de stacking vertical.
- **Deploy:** Producción NO es build estático — el contenedor `frontend` corre `npm install && npm run dev` (Vite dev, volumen `./frontend:/app`, puerto 3003). El sitio live está en VPS `178.104.36.180` (tailscale `agora-scout.tail127286.ts.net`). `npm run build` local es irrelevante (y falla por node_modules local sin react-router-dom — no afecta prod). Fix entregado por `scp` de `dashboard.css` + `App.jsx` al working tree del VPS → Vite HMR recarga vía volumen. NO se usó deploy.sh (hace `build --no-cache backend`, innecesario para CSS).
- **Verificado:** scp OK (uploaded). Falta confirmación visual del usuario tras hard-refresh.

## 2026-06-08 (cont.) — CAUSA RAÍZ REAL: colisión de clase `side` (no era el grid)
- **Lo de grid→flex fue desvío.** El revert a Grid no arreglaba el visual. Diagnóstico vía DevTools (computed styles del usuario): el `.market-flag` medía **1214px de alto** (`position:sticky`, `height:calc(100vh-64px)`), empujando verdict-big/safe-meter/conf a `top:1352px` (fuera de pantalla). Por eso el panel se veía como tira vacía.
- **Causa:** la clase `side` se usa para DOS cosas distintas: (1) `<aside className="side">` = sidebar, con regla `.agora-dash .side{position:sticky;top:64px;height:calc(100vh-64px)}`; (2) `rclass('SIDEWAYS')` devuelve `'side'`, aplicado al market-flag (`market-flag side`) y a los `.mtag side` del log. El selector descendente `.agora-dash .side` matchea CUALQUIER hijo con clase `side` → el flag heredaba la altura del sidebar. Solo rompía en régimen SIDEWAYS (bear/bull no colisionan). Los tags del log no explotaban porque `.mtag` tiene `max-height:25px` que capa la altura; el market-flag no tenía cap.
- **Fix:** calificar la regla del sidebar a `aside.side` (base + media query). Cambio mínimo, sin tocar JS. El span del flag ya no matchea.
- **Descartado:** NO era extensión de navegador (reprodujo en incógnito). NO era caché (DevTools confirmó computed real). El `#adopted-style-sheets` fue otro desvío.
- **Deploy:** scp dashboard.css al VPS + `docker restart agora-scout-frontend` (HMR sobre volumen no recargaba fiable). Verificado: served CSS = `aside.side{...}`.
- **Footgun pendiente:** clase genérica `side` como modificador de régimen es peligrosa. Mejor a futuro: renombrar `rclass` 'side'→'sideways' y los selectores `.mtag.side`/`.market-flag.side`. Por ahora el `aside.side` corta el sangrado.
